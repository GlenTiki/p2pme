01

Install the library

The local host runs on your computer. The public website supplies the browser app and instructions. It cannot install a skill inside your agent.

The first release targets Node.js 22 or later. Review the source and release before you install it.

PLANNED RELEASE · 0.1.0npm install --global https://github.com/GlenTiki/p2pme/releases/download/v0.1.0/glentiki-p2pme-0.1.0.tgz

This release URL is provisional. Use it only after version 0.1.0 is published.

02

Register a session

Install the pinned release package from step 1. Copy its packaged skills/p2pme folder into your project's skill directory. The live skill page is reference text only. It cannot authorize a device or install itself.

LOCAL HOST · KEEP THIS TERMINAL OPEN p2pme host --workspace /absolute/path/to/project

Copy the packaged skill folder into your project's skill directory. Codex uses .agents/skills/p2pme. Claude Code uses .claude/skills/p2pme.

Invoke $p2pme in Codex or /p2pme in Claude Code. The skill needs the exact current session ID.

Use p2pme register codex THREAD_ID for a supported Codex thread. Use p2pme start codex or p2pme start claude to create a new managed session.

Run p2pme status to check the host ID and session IDs.

Host ID
Identifies your local host. Keep one host for the sessions you register on this computer.
Session ID
Identifies one registered agent session. Select this session after you connect to the host.

The skill registers your chosen session. It does not expose every session on your computer.

Claude Code and Codex

For your current Claude session, run p2pme claude-setup CLAUDE_SESSION_ID --output-dir /absolute/new-directory. Use the exact session ID. The command creates separate configuration files and prints a resume command. Exit the selected Claude process first. Run the printed command from the host-approved workspace. Approve the native channel and MCP prompts. Do not run two copies of the same session. The setup command does not edit your existing settings or launch Claude.

Codex requires a supported session adapter. The adapter must identify the selected thread. A new managed session must be labelled as new.

A skill cannot attach to every running agent session. Follow the adapter instructions for your host.

03

Pair your browser

  1. Open p2pme.glentiki.dev on your phone.
  2. Name the browser and choose whether it should remember the host.
  3. Select Create invitation. Copy the agent prompt to your local session.
  4. Run p2pme pair --profiles codex in your own terminal. Paste the invitation through stdin. End input with Ctrl-D.
  5. Check the displayed scope. Type approve at the foreground host terminal prompt.
  6. Select a registered session to send a message.

You do not need an account. A remembered host lets you return to its registered sessions. You can revoke the device separately from a session. Use p2pme revoke GRANT_ID to revoke host access.

Select --profiles claude for Claude or --profiles codex,claude for both. A profile list is required.

The default grant allows session lists and chat for registered sessions. It expires after 30 days. An invitation is a bearer secret. Its label does not prove a person's identity.

Your agent keeps its local tool and file permissions. The browser does not approve those actions for you.

UNDER THE HOOD

Two paths. One library.

Native agent peers use Hypercore message logs and Hyperswarm connections. The browser uses WebRTC to reach the local peer.

GitHub Pages serves the static app. Public Nostr relays at nos.lol and relay.damus.io carry encrypted discovery offers. Google and Cloudflare STUN servers help peers connect. These services can see connection metadata.

The app contacts those services only after you select Connect or Create invitation. It operates no hosted chat server. Direct connections can fail on restrictive networks. An operator can supply TURN; that relay can incur costs.
