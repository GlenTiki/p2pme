# Local host daemon and command line

Status: accepted and implemented. This slice connects the persistent host, approved browser transport and provider adapters. It does not change user shell, Codex or Claude settings.

## Local process and socket

`p2pme host --workspace PATH` starts a foreground daemon on macOS or Linux. The workspace must be an existing absolute local directory. A private `daemon.json` records its canonical path, device and inode before any grant is accepted. Startup with a different workspace identity fails closed and requires a separate state directory. Existing grants cannot silently gain access to another workspace through the same profile ID. The default state directory is `~/.p2pme`; `--state-dir PATH` selects another directory. The host store creates a mode-0700 directory and holds its exclusive lock. Startup rejects symlink state directories, wrong ownership and non-directory paths. The daemon sets umask 077 before it binds the socket. It rejects socket paths longer than 103 UTF-8 bytes on macOS or 107 bytes on Linux. The daemon creates `control.sock` inside it and sets mode 0600. It listens only on that Unix socket. An existing socket or file causes startup to fail, including after a crash. The operator must confirm the old process has stopped, then remove its stale socket and lock; the program does not delete an unknown socket or seize another daemon's state.

The local user and their processes are trusted. The socket is not a proof of human authorship. The skill must not forge local approval or send grant-management calls as Glen. The daemon accepts a closed list of local JSON requests. It caps each frame at 32 KiB, each connection at one request and concurrent connections at 16. Errors contain a fixed public message rather than provider credentials or paths. Shutdown closes connections, peer rooms, adapters and logs, then removes the socket only when its device and inode still match the file this daemon created. SIGINT and SIGTERM use the same shutdown path. It releases the store lock on clean shutdown and leaves persistent host state intact.

The local `HostController.sessions()` method returns registered metadata and current online state. The daemon uses this method for status. It is not a remote unauthenticated operation.

## Provider profiles

The daemon supplies local `codex` and `claude` profiles bound to its startup workspace. Their metadata uses `provider-default` to describe the provider's existing model default. The provider factory receives an absent model option, not the literal model name `provider-default`. These baseline profiles do not approve remote model changes. Labels can still change. Provider approval and sandbox policies remain with the supported adapter. Remote callers cannot change workspace, executable, CLI arguments, environment or permission policy.

`p2pme start codex` and `p2pme start claude` create a managed session through the selected local profile. `p2pme register codex THREAD_ID` attaches only the explicit running Codex thread through the supported proxy. Registration verifies the provider thread working directory against the pinned workspace before attaching. An absent or mismatched directory fails closed. Attachment failure is an error. It does not silently create a replacement conversation. No command sends an initial model prompt.

Claude's native Channel process needs a separate local attachment bridge. This slice uses the supported managed Claude adapter for `start claude`; it does not claim that this command attaches to the current Claude terminal. The repository skill must state the current-session Channel registration path separately.

## Pairing and grants

`p2pme pair` reads one bounded invitation from stdin. It does not accept the invitation as a command argument. The command and daemon decode and validate the invitation. Labels must be NFC, 1–100 characters, and contain no Unicode control, format, line separator, paragraph separator or unassigned characters (`Cc`, `Cf`, `Zl`, `Zp`, `Cn`). The daemon then displays the device label with `JSON.stringify`. Status uses JSON output with terminal-unsafe characters escaped. The daemon opens its own `/dev/tty` for an explicit human approval prompt. Every pair request reaches this daemon-owned gate, including a request sent directly to the local socket. A pipe, `--yes` flag or stdin text cannot answer that prompt. The exact principal, scopes, profiles, workspace identity, registered-session access and expiry appear before approval. The prompt states that approved profiles expose current and future registered sessions. It states that chat and task scopes let the selected provider use its existing tools and return local file content. An agent principal does not grant extra authority. The only affirmative response is the literal word `approve`. A missing controlling terminal, a rejected answer or expiry fails closed. The prompt uses the already validated immutable request; the daemon validates it again.

The default principal is `human-device`; `--agent` selects agent content. Default scopes are `sessions:list,sessions:chat`. `--scopes` selects an explicit comma-separated subset, including separate create, configure, delegate and UI permissions. `--profiles` must supply an explicit nonempty list of locally configured profiles. An omitted list fails closed. Unknown flags, scopes or profiles fail before pairing. Grants initially expire after 30 days; that fixed policy is displayed during approval. The daemon generates separate persistent room credentials. An invitation does not become a grant before its peer acknowledgement. The daemon permits one pending pair operation. It persists the invitation ID as used before joining the room and retains that ID until invitation expiry, including after revocation or restart. Pending pair operations end at invitation expiry or when their local requester disconnects. An already persisted grant survives requester disconnect; its activated room remains locally revocable.

After the browser acknowledges the proposed permanent connection, the daemon atomically persists the grant, then opens its approved room. It restores only unexpired, unrevoked grants on restart. Restoring a grant does not attach old sessions or restore a transcript. Expiry closes its room through the transport timer. `p2pme revoke GRANT_ID` requires the running daemon. It revokes the host grant and closes that room. Offline commands do not edit the store. Expiry and revocation reject new turns and suppress later output; a provider may already have performed actions before abort. A persistence failure stops remote dispatch through the existing store health check. Pairing secrets and permanent room secrets do not appear in stdout, status or application errors.

Public rendezvous and STUN services are the configured transport's external dependencies. Starting the daemon with remembered active grants opts into their reconnection. A host with no active grants does not join rooms until a locally approved pair operation. The CLI does not claim that restrictive NATs always connect or that a third-party relay has no operating costs.

## Other commands

`p2pme status` returns host ID, epoch, profiles, registered sessions and grant summaries. It excludes room IDs and secrets. `p2pme ui publish SESSION_ID FILE` reads a bounded JSON file and submits it to the host's local validated surface API. It does not bypass the UI catalog or publish a renderer function. The surface registry is provided by its own reviewed slice.

Each local control request has a request ID, an operation and typed arguments. The daemon permits only status, register, start, pair, revoke and publish. It never accepts an executable string, a shell command or an arbitrary provider RPC. The client checks that the socket is a current-user-owned socket inside a private directory before connecting. The client bounds reads and response time. The daemon closes an idle client after ten seconds without a complete first frame. Pairing uses the invitation's validated deadline, at most ten minutes; other local operations have a fixed 60-second deadline.
