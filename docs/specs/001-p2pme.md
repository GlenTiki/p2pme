# p2pme project contract

## Intent

p2pme is Glen Keane's open-source library for agent communication. A local host exposes approved agent sessions to a browser or another agent. The browser app also presents the project and links to [Glen's website](https://glentiki.dev) and [the repository](https://github.com/GlenTiki/p2pme).

Glen selected Hypercore, Claude Code, Codex, device pairing with local approval, and separate grants for session creation and task delegation. He selected a static site with no operated application backend. The project uses GitHub Pages at `p2pme.glentiki.dev`.

## Architecture

Hypercore stores signed, bounded session logs. Hyperswarm connects explicitly approved native peers. Trystero connects the browser to the local host through WebRTC. Public discovery relays and STUN servers help peers find each other. The browser does not join the Hypercore DHT.

The local daemon holds the persistent host ID, registered session mappings and device grants. Each daemon start creates a new epoch. Each registered session has its own ID. A browser can remember an approved host and select a registered session after reconnect.

The host checks every remote operation against the current grant. Session lists, chat, creation, configuration, task delegation and UI actions have defined scopes. The remote caller cannot supply executable paths, workspace paths or permission policies. Registered sessions retain their provider's local tool permissions.

The browser renders a fixed catalog of reactive controls. Inputs can change text and visibility. An explicit button sends a typed action to the host. Surface content cannot execute code, fetch URLs or approve tools.

## User flow

1. Install the release package and the selected provider CLI.
2. Start the local host with an explicit workspace.
3. Register an existing supported session or start a managed session.
4. Open the browser app and create a device invitation.
5. Run the local pair command with explicit profile IDs.
6. Paste the invitation through stdin.
7. Approve the displayed grant in the foreground host terminal.
8. Select a registered session in the browser.
9. Send a message or submit an approved surface action.

The `/host/` route contains setup instructions. The packaged skill guides local setup. A website cannot install the skill or grant local access by itself. Codex invokes the skill as `$p2pme`; Claude Code uses `/p2pme`.

## Session read and write

A provider adapter submits a remote request and returns its correlated output. Codex uses app-server JSON-RPC. Its attachment path uses the running control socket. Claude uses either a managed process or a native Channel. Native Claude setup requires an explicit resume with MCP and hook configuration. It cannot hot-attach to any arbitrary running process.

These adapters do not mirror the full local conversation. A transcript observer would be a separate read capability. It would need explicit session selection, a bounded history window, record validation and file replacement handling. A transcript file is an output record; appending text does not establish a supported input channel. Provider write APIs remain the control path.

Provider contract tests use simulated processes and MCP clients. Real transport tests use Chromium, Node, Hypercore and a local discovery relay. Those tests do not prove compatibility with every installed provider version. A live provider test must precede a claim of verified control of that provider's current session.

## Acceptance criteria

1. A clean Node.js installation can install the release tarball without files from Glen's workspace.
2. Real native peers replicate validated entries through Hypercore and Hyperswarm.
3. Real Chromium and Node peers exchange authenticated host requests through WebRTC.
4. Pairing requires explicit local approval and grants only the selected profiles and scopes.
5. Host identity and approved grants survive restart. Provider sessions remain offline until explicitly attached.
6. Revocation and expiry block later commands and output.
7. The browser selects a session before chat or an action. Invalid or stale surface actions fail.
8. The mobile page has usable controls, clear errors and links to Glen and the source repository.
9. Types, lint, complexity checks, format checks, tests, builds and a clean package smoke test pass.
10. Independent review covers the source, boundaries and failure paths before release.
11. The public repository includes its licence, contribution policy, security policy, CI, examples and exact install instructions.

## Boundaries

The local operating-system account and delivered website code are trusted. Device credentials prove possession of an approved grant, not human authorship. Agent messages remain agent content. Model permissions remain local. Chat can cause existing tools to run and can return local content within those permissions.

Static hosting removes an operated p2pme application server. It does not remove domain, model or optional relay costs. Restrictive networks can prevent direct WebRTC access. Public discovery services can observe connection metadata and can become unavailable.

This release excludes account identity, transcript archives, remote tool approval, arbitrary shell access, automatic local session discovery and an A2A standards-compliance claim.

## Rejected alternatives

The first draft used a Cloudflare Worker and Durable Object for rendezvous. Glen's cost constraint superseded that design. Public discovery relays permit automatic peer setup without an operated p2pme service. Manual offer and answer exchange remains unnecessary in the selected flow.

Hyperswarm alone cannot provide the browser transport. A custom Hypercore browser storage port would add maintenance. Native Hypercore and a separate WebRTC adapter preserve the requested foundation with supported packages.
